# MoE Training

MoE（Mixture of Experts，混合专家）训练方法通过激活模型中的一小部分"专家"子网络来处理每个输入，实现用更少的计算获得更大的模型容量。

## 核心架构

MoE 模型的关键组件：
- **专家网络（Experts）**：多个独立的前馈网络
- **门控网络（Router/Gating）**：决定每个 token 激活哪些专家
- **Top-K 选择**：通常每个 token 选择 2-4 个专家
- **负载均衡**：确保专家之间的负载均匀分布

## 训练挑战

### 负载均衡

- 专家之间容易出现"赢者通吃"
- 部分专家被过度使用，其他专家闲置
- 解决方案：辅助损失函数、Expert Choice 路由

### 通信开销

- 分布式训练时，专家分布在不同 GPU
- token 需要在 GPU 之间传输
- 解决方案：Expert Parallelism、All-to-All 通信优化

### 训练稳定性

- 门控网络的梯度不稳定
- 路由决策的离散性导致训练困难
- 解决方案：Straight-Through Estimator、辅助损失

## DeepSeek 的 MoE 创新

[[DeepSeek]] 在 MoE 训练方面有多项创新：
- **DeepSeekMoE**：更细粒度的专家划分
- **共享专家**：部分专家始终被激活
- **无辅助损失负载均衡**：创新的负载均衡策略
- **FP8 训练**：大规模 FP8 混合精度训练

## 优势与劣势

| 优势 | 劣势 |
|------|------|
| 更大模型容量 | 训练复杂度高 |
| 推理效率高（仅激活部分） | 通信开销大 |
| 计算效率好 | 负载均衡困难 |
| 可扩展性强 | 内存需求高 |
