# Quantization

Quantization（量化）是将模型参数从高精度（如 FP32）转换为低精度（如 INT8、INT4）的技术，以减少模型大小和推理成本，同时尽量保持模型质量。

## 量化类型

| 类型 | 说明 | 精度损失 |
|------|------|---------|
| FP16/BF16 | 半精度浮点 | 极小 |
| INT8 | 8 位整数 | 小 |
| INT4 | 4 位整数 | 中等 |
| GPTQ | 基于二阶信息的量化 | 小 |
| AWQ | 激活感知权重量化 | 小 |
| GGUF | 通用格式，支持多种量化 | 可变 |

## 量化方法

### 训练后量化（PTQ）

- 在训练完成后对模型进行量化
- 无需重新训练，成本低
- 代表：GPTQ、AWQ、GGUF

### 量化感知训练（QAT）

- 在训练过程中模拟量化效果
- 精度损失更小，但需要训练资源
- 代表：[[Microsoft]] 的 BitNet

### 混合精度

- 不同层使用不同精度
- 敏感层保持高精度，其他层量化
- 平衡精度和效率

## 推理框架

| 框架 | 特点 | 支持平台 |
|------|------|---------|
| llama.cpp | CPU 推理，GGUF 格式 | CPU/GPU |
| vLLM | 高吞吐推理 | GPU |
| TensorRT-LLM | [[NVIDIA]] 优化推理 | GPU |
| MLX | [[Apple]] Silicon 优化 | Apple 芯片 |
| TGI | HuggingFace 推理服务器 | GPU |

## 实际效果

以 [[Llama 4 Scout]] 为例：

| 精度 | 模型大小 | 推理速度 | 质量损失 |
|------|---------|---------|---------|
| FP16 | ~140GB | 1x | 0% |
| INT8 | ~70GB | 1.5x | <1% |
| INT4 | ~35GB | 2x | 1-3% |
| GPTQ-4bit | ~35GB | 2x | <2% |

## 行业应用

- **端侧部署**：手机、IoT 设备上的 AI
- **边缘计算**：降低延迟和带宽成本
- **大规模推理**：降低 GPU 内存需求
- **[[Apple]] Intelligence**：端侧 3B 模型量化部署
- **[[Xiaomi]]**：手机端 AI 功能的量化优化

## 与其他方法的关系

- **[[Distillation]]**：先蒸馏再量化，效果更好
- **[[LoRA]]**：量化 + LoRA（QLoRA）降低微调成本
- **[[MoE Training]]**：MoE 模型的专家可以独立量化
