# Speculative Decoding

Speculative Decoding（投机解码）是一种通过使用小型"草稿"模型预测多个 token，再由大型"验证"模型批量验证来加速大语言模型推理的技术。

## 核心原理

标准自回归解码的瓶颈：
- 每次只生成 1 个 token
- 每个 token 都需要完整的模型前向传播
- GPU 利用率低（内存带宽受限）

投机解码的解决方案：
1. **草稿模型**（Draft Model）快速生成 K 个候选 token
2. **目标模型**（Target Model）一次性验证所有 K 个 token
3. 接受正确的前缀，拒绝第一个错误位置之后的 token
4. 从拒绝位置重新开始

## 关键特性

| 特性 | 说明 |
|------|------|
| 无损加速 | 数学上保证与原模型输出分布完全一致 |
| 加速比 | 通常 2-3x，取决于草稿模型质量 |
| 适用场景 | 批量大小为 1 的推理（交互式使用） |
| 硬件要求 | 主要受 GPU 内存带宽限制 |

## 草稿模型选择

| 类型 | 说明 | 代表 |
|------|------|------|
| 小型同系列模型 | 从同系列的小模型草稿 | Llama 3 8B → Llama 3 70B |
| [[Distillation]] 蒸馏模型 | 从目标模型蒸馏 | 专门训练的草稿模型 |
| [[Quantization]] 量化模型 | 量化版本作为草稿 | INT4 版本 |
| Medusa 多头 | 模型自身添加预测头 | 不需要额外模型 |
| EAGLE | 基于特征的自回归草稿 | 高质量草稿 |

## 实现方案

- **标准投机解码**：独立草稿模型
- **Medusa**：在目标模型上添加多个预测头
- **EAGLE**：使用目标模型的特征进行草稿预测
- **Lookahead Decoding**：基于 Jacobi 迭代的并行解码
- **Staged Speculative Decoding**：多阶段草稿和验证

## 与其他加速方法的关系

| 方法 | 作用 | 与投机解码的关系 |
|------|------|----------------|
| [[Quantization]] | 减少模型大小 | 可结合使用 |
| [[Distillation]] | 减少模型参数 | 蒸馏模型可作为草稿 |
| KV Cache 优化 | 减少内存 | 互补 |
| 批量推理 | 提高吞吐 | 投机解码对批量推理效果有限 |

## 行业影响

投机解码已成为大模型推理优化的标配技术：
- [[Google]] Gemini 使用投机解码
- [[OpenAI]] 的推理服务疑似使用类似技术
- 开源框架普遍支持
- 2-3x 的加速对用户体验有显著提升
